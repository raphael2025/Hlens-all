# 通知通道的凭据泄漏面审计：一次完整的排查与验收协议

告警通道是整个监控系统里**唯一必须持有外发凭据**的地方。它每一条告警都要把一个 bot token 或 webhook 密钥送到进程外面去，而告警本身的天职又是"出事的时候把上下文尽可能完整地吐出来"——这两件事天然打架。

这份文档整理自一次针对推送通道的只读审计：审计的目标不是"代码里有没有硬编码密钥"（那只是第一分钟的工作），而是**把凭据可能流出去的每一条路径逐条列出来，逐条实测，并给出一份可以由人执行的验收协议**。

审计最终找到 6 个缺口，其中两个足以让"一次用来证明不泄漏的验证"以**打印明文凭据的 traceback** 收场——正是它本来要防的事故形态。

---

## 一、先扫历史，不是只扫工作区

第一步不是读代码，是确认仓库**当前和历史上**都没有真凭据：

| 检查 | 做法 |
|---|---|
| 工作区形态扫描 | 对凭据的**形状**做正则扫描（例如 `数字{8,10}:[A-Za-z0-9_-]{35}` 这类 bot token 形态），而不是只搜 `token=` 这种变量名 |
| **历史扫描** | `git log --all -p` 全量打出来再过同一条正则——工作区干净不代表某次提交里没进去过 |
| 忽略规则 | 确认运行期产物目录（状态文件、日志、数据库）在 `.gitignore` 里是**根锚定**的，并且当前确实是空的 |
| 运行产物快照 | 确认任何"环境快照"类功能是**白名单**采集，而不是 `os.environ` 全量转储 |
| 读环境变量的位置 | `grep -rn "os.environ" src/` 逐个确认，应该屈指可数且用途明确 |

命中项要逐条解释清楚"为什么它不是真凭据"——是常量 URL、是变量名、还是测试假值。**测试假值应该一眼可辨**（例如 `unit-test-token-not-real`），而不是一串看起来很像真的随机字符：后者会让每一次扫描都要人来判断，久而久之就没人判断了。

## 二、泄漏面清单（逐条实测，不靠读代码想象）

这是本次审计最有复用价值的部分。**每一行都是一条独立的出口**，漏掉任何一行都可能让前面所有工作白做：

| 泄漏面 | 要验证什么 |
|---|---|
| `repr` / `str` / f-string | 凭据对象的 `__repr__` 要覆写成掩码，并且 `__str__ = __repr__`；**持有它的外层对象**（普通 dataclass）的默认 repr 会递归调用它，也要实测一遍 |
| URL | Bot API 这类形态下 URL 里必然含明文凭据，**这无法避免**。关键是这个 URL 绝不能出现在任何返回值、日志或落盘记录里——成功路径应该返回一个**常量**掩码串，而不是对真 URL 做掩码 |
| 异常消息 | 注入各种形态的异常，看掩码逻辑是否都能覆盖 |
| **未捕获异常** | 捕获的异常元组是否漏掉了某一类？漏掉的那一类会直接抛穿调用方 |
| 日志 | 理想状态是这个模块**零 logging 调用、零 print**，根本不存在日志泄漏面 |
| 结构化落盘记录 | 记录的字段 schema 里是否根本没有凭据字段；**自由字段**（如 `context`）是否过滤 |
| 结果对象字段 | 返回给调用方的结果对象是否持有凭据引用——打印整个结果对象会怎样 |
| 测试夹具 | 假值是否一眼可辨为假值 |
| 进程 argv | 凭据的**注入方式**决定这一条：环境变量不进 argv（`ps` 看不到），命令行内联则会进 |
| `/proc/<pid>/environ` | **同 UID 可读**。进程存活期间，任何同用户进程都能读到它的环境变量 |
| 环境快照产物 | 白名单还是全量转储 |
| 缓存与全局 | 凭据唯一的驻留处应该是进程内的一个字段，没有模块级全局，没有任何持久结构缓存它 |

## 三、实际找到的 6 个缺口

### 缺口 1：应答不可解析被记成"已发送"（影响最大的一条）

解析响应 JSON 失败时返回 `None`，而调用处只在"明确为失败"时判失败——`None` 就落进了成功分支。实测：

| 传输层返回 | 判定 |
|---|---|
| `{"ok": true}` | 已发送 ✅ |
| `{"ok": false, ...}` | 失败 ✅ |
| `<html>proxy error</html>` | **已发送** ❌ |
| 空字符串 | **已发送** ❌ |
| 合法 JSON 但不是对象 | **已发送** ❌ |

现实触发场景非常普通：中间设备（代理、门户认证页、运营商劫持）返回 HTTP 200 加一段非 JSON 正文。

**为什么这条最严重**：假的"已发送"会写进去重抑制表，于是接下来一段时间内同一去重键的**真**告警会被当成重复的压掉。也就是说，一次网络中间件的干扰不只是丢一条告警，而是**让这一类告警在一段时间内彻底静音**。

> 结论：**"程序说发出去了"不是送达证据。** 修法是把"不可解析"降级为失败，或者新增一个"未验证"状态——绝不能进成功分支。

### 缺口 2：异常类型漏捕获，抛穿 + 明文进 traceback + 落盘零记录

捕获元组写的是 `(URLError, OSError, ValueError)`，漏掉了 `http.client.HTTPException` 这一支（`InvalidURL`、`BadStatusLine` 等**都不是** `OSError`/`ValueError` 的子类）。实测同时破裂三件事：

1. 文档承诺的"发送函数永不抛异常——告警通道挂掉不得反过来打死调用方"，破了；
2. 文档承诺的"结构化文件是唯一保证可用的通道"，也破了——因为落盘发生在**投递之后**，异常一抛，这条告警在文件里连痕迹都没有；
3. 异常正文**含明文凭据**：凭据里混入一个空格或控制字符（粘贴失误的典型后果），底层库会在**建立连接之前**就抛 `URL can't contain control characters. '/bot1234 56:.../sendMessage'`。

**触发条件极其现实**：一次粘贴失误。而失误的后果是一份含明文凭据的 traceback 打进了终端 scrollback。

> 修法三件事：①捕获兜底；②**把结构化落盘挪到投递之前**，投递结果回填；③掩码改成对凭据字面量做替换。

### 缺口 3：掩码只认 URL 前缀

掩码实现是靠定位 `/bot` 然后掩到下一个 `/`。实测一条形如 `auth failed for token <凭据>` 的异常文本会**原样进记录并落盘**。

现实触发概率低，但它是**兜底掩码的兜底**，不该有洞。

> 修法：先对 `凭据字面量` 做一次 `replace(token, "<redacted>")`，再叠加现有的前缀规则。**掩码要基于"我知道的秘密值"，而不是基于"我猜秘密会出现在什么语法结构里"。**

### 缺口 4：自由字段零过滤

结构化记录里有一个 `context` 字典字段，原样落盘。实测把凭据塞进 context 就会明文落地。

这不是现存缺陷（当前没有调用方这么干），而是**未来调用方的陷阱**：接线的人很容易把整个请求 payload 塞进 context。

> 修法：落盘前对 value 跑一遍掩码，或者给 context 建键白名单。

### 缺口 5：序列化函数绕过掩码

`dataclasses.asdict(credentials)` 会**绕过 `__repr__` 掩码**直接吐出明文。当前全仓没有调用方碰到凭据，但这是一个标准的"将来有人把整个配置树 asdict 一下"事故。

> 修法：在凭据类型上阻断序列化路径（自定义 `__getstate__` 或显式抛错），而不是靠约定。

**推广一下**：凡是靠覆写 `__repr__` 来做掩码的地方，都要同时检查 `asdict` / `json.dumps(default=...)` / `pickle` / ORM 序列化 / 日志库的结构化字段这几条**绕过路径**。掩码只挡住了人类可读的那一条。

### 缺口 6：告警通道根本没有生产侧调用方

`grep` 全仓，除了模块自身之外**零命中**。也就是说这次验证能证明的是"适配器能把消息送达"，**不等于**"系统真出事时它会自己喊"。

这一条被和另一个发现（外部 dead-man's-switch 全仓零实现）并列记进已知缺口——**两者都属于"真出事那天才会发现没接线"的同一类风险**。这类风险的特征是：所有单元测试都绿，所有人都以为有，直到第一次真事故。

## 四、验收协议：怎么做一次"只发一次真消息"的人工验证

自动化测试能验证的是逻辑；"消息真的到了手机上"只能由人确认一次。下面这套协议的设计目标是：**这一次真实投递本身不能造成泄漏。**

### 执行前三条硬规则

1. **凭据只进你自己的 shell，只活这一次。** 全程不写任何文件、不进仓库，输出目录固定在临时目录。用 `read -rs` 输入 → 不回显、不进 shell 历史、不进任何进程的 argv。**不要用命令行内联**（`FOO=xxx cmd`）——那会把凭据写进 `~/.bash_history` 和终端 scrollback。
2. **执行期间不要让任何 agent 会话跑 bash。** 环境变量虽然不进 argv，但 `/proc/<pid>/environ` **同 UID 可读**，暴露窗口大约一两秒——把它留空即可。
3. **判定以"人工确收"为准，不以程序输出的"已发送"为准**（原因见缺口 1）。

### 步骤 A — 注入凭据并做形态自检

输入之后立刻用纯 shell 内建做一次形态校验（凭据不进 argv）：

```bash
[[ "$TOKEN" =~ ^[0-9]+:[A-Za-z0-9_-]+$ ]] \
  && echo "形态 OK" || echo "形态异常（混入空格/换行/引号？）—— 停，重输"
```

这一步就是专门为缺口 2 设的护栏：**在凭据进入任何库之前就拦下畸形值**，因为畸形值会让异常路径打印明文。

### 步骤 B — 一次真实投递，覆盖所有分级

一次跑完全部严重度等级，每条消息带一个**本次编号**（时间戳生成）。编号的作用是排除"收到的是上一次残留的消息"这种误判。刻意**不传** `context` 字段（规避缺口 4）。

### 步骤 C — 事后自检，机器验证而不是肉眼

```bash
# 形态扫描：产物里不该出现任何凭据形状的串
grep -RnE '<凭据形态正则>' "$OUT_DIR"; echo "期望 exit=1（无匹配）"

# 精确扫描：pattern 走管道喂进去（printf 是 shell 内建 → 凭据不进任何进程 argv）
printf '%s\n' "$TOKEN" | grep -RFf - "$OUT_DIR"; echo "期望 exit=1"

# shell 历史复核（兜底）
printf '%s\n' "$TOKEN" | grep -Ff - ~/.bash_history; echo "期望 exit=1"

# 仓库零污染
git status --short   # 期望空
```

注意 `printf '%s\n' "$TOKEN" | grep -Ff -` 这个写法：**把要搜索的秘密通过管道喂给 grep，而不是作为命令行参数**，否则这条检查自己就成了一次泄漏。

### 步骤 D — 销毁凭据

`unset` 掉，并打印确认。

### 判定清单要分三组

- **终端输出**：配置已加载、各级状态符合预期、**掩码字符串逐字符相符**、输出中看不到凭据。掩码失效 = 安全事故，立即停，不是"改不改通过"的问题。
- **人工观察（唯一的送达证据）**：收到的条数、该响铃的响了、该静默的静默到达、**不该推送的那一级确实没到**（等 60 秒再确认一次）、编号与终端一致。
- **结构化文件**：行数、各行状态、字段完整、**全文不含凭据**（由 C 步的扫描机器验证，不靠肉眼）。

### 明确禁止的推理

> "终端打印了『已发送』 ⇒ 消息实际到达"

缺口 1 已经证明这个推理不成立。冻结的验收标准写的是"实际送达"，所以**只有人工观察能关闭它**；缺人工观察时，状态维持"待定"——不允许因为"看起来都对"就改成通过。

## 五、失败诊断树按"从最便宜到最贵"排序

收不到消息时，按成本递增顺序排查，每一步都能靠**已有输出**区分，不需要再发一次真消息：

| 现象 | 判定 | 处置 |
|---|---|---|
| 配置未加载，全部报"未配置" | 环境变量没进到进程：变量名拼错、漏 export、步骤 A 与 B 不在同一个 shell | 重跑注入 |
| 失败 + 401 | 凭据无效：复制少了尾字符，或已被重置 | 重新获取。**别把它写进任何文件** |
| 失败 + 400 | 目标 ID 错 | 重新获取目标 ID |
| 失败 + 403 | 对方没有先主动建立会话，或机器人被移出 | 先建立会话再重跑 |
| 每条卡约 10 秒后失败，连接类错误 | 出站网络不通：DNS、代理、网络策略 | 先测 DNS，再看是否要配代理 |
| **状态"已发送"但没收到** | 高度可疑 = 缺口 1：中间设备返了 200 + 非 JSON | **判失败，不得通过** |
| 不该推送的那一级也到了 | 分级策略被破坏 | **直接失败**，回查配置常量与调用处 |
| Python 抛异常退出，traceback 里出现明文凭据 | 缺口 2 命中 | **立即：①清屏并清除 scrollback；②unset；③认为该凭据已在本机泄漏，直接吊销重置。** 然后再来 |

最后一行是这份协议里最重要的一条操作纪律：**一旦明文凭据出现在任何可能被记录的地方（终端 scrollback、history、日志、traceback），就按已泄漏处理，直接吊销。** 不要评估"应该没人看到吧"。

## 六、可以抄走的几条结构性结论

1. **掩码要分三层**：构造期做形态自检（挡畸形值引发的底层异常）、运行期对凭据字面量做替换（不依赖语法结构猜测）、落盘期做字段白名单（挡自由字段）。任何一层单独存在都有洞。
2. **结构化记录必须先于外发写入。** 如果落盘排在投递之后，投递路径上的任何异常都会让这条记录彻底消失——而那恰恰是你最需要它的时候。
3. **把"未配置"和"失败"分成不同状态**，不要折叠成一个布尔值。五态（未配置 / 失败 / 按策略跳过 / 去重 / 已发送）读日志时的信息量远大于 `pushed: false`。
4. **环境快照一律用白名单**，永远不要 `os.environ` 全量转储进产物。
5. **审计报告自己也要零凭据**：本次报告里所有示例 token 都是刻意拼接书写的假值，专门避免报告自身命中协议里的形态扫描。写审计报告的人，是最容易在报告里粘一份真值的人。
6. **"能送达"和"出事时会自动喊"是两件事。** 验证了适配器，不等于验证了接线。把"零生产调用方"和"无外部 dead-man's-switch"并列记进已知缺口，别让它们藏在"测试全绿"背后。

---

## 一句话总结

> 一个防泄漏的验证，如果自己会在失败路径上打印明文凭据，那它就是本轮要防的那个事故。**审计的第一个对象，是审计动作本身。**
