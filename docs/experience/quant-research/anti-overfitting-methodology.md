# 反过拟合方法论：让回测说真话

这份文档回答一个问题：**一条漂亮的资金曲线，凭什么可以相信？**

绝大多数回测结果是假的。不是因为作者不诚实，而是因为"在历史数据上找一条赚钱的规则"这件事本身，天然会产出假阳性。下面是我们在多轮独立研究中反复撞墙之后，收敛出来的一套检验流程，以及它到底在防什么。

---

## 一、回测为什么会撒谎：三个安静的杀手

1. **前视偏差（look-ahead bias）**
   使用了在决策时点根本拿不到的信息。最隐蔽的版本不是"用了明天的收盘价"，而是各种标注类逻辑：把一个摆动高点标注在"现在"，而实际上你要再过两根 K 线才知道它是高点；或者用全样本统计量（expanding mean / expanding z-score）去标准化当前值。

2. **成本与滑点被忽略**
   很多 edge 在纸面上是真的，扣掉 taker 手续费、资金费、滑点之后就没了。换手率越高越致命——一个分钟级信号可以把纸面上的正年化打成深度负值，纯粹靠交易成本。

3. **多重检验（最大的那个）**
   扫 200 组参数，最好的那一组**必然**好看，这是统计规律不是发现。大多数公开的回测结果，本质上是一次未被披露的搜索的冠军。

朴素回测对这三样一个都抓不住。整套检验流程就是为了抓住它们。

---

## 二、检验清单：每一项在防什么

| 检验 | 防什么 |
|---|---|
| 无前视构造 | 前视偏差——信号打在"被确认"的那根 bar 上，而不是"起源"的那根 |
| 成本内化收益 | 手续费/滑点/资金费致死 |
| Deflated Sharpe（DSR） | **多重比较**——按"你到底试了多少种配置"折算显著性 |
| Probabilistic Sharpe（PSR） | 非正态分布下，真实 Sharpe 是否超过某个基准 |
| PBO（CSCV） | 样本内最优在样本外变垃圾的概率 |
| 块自助（block bootstrap） | 脆弱的 Sharpe 和被低估的回撤——给出 Sharpe 置信区间和真实最坏回撤 |
| Placebo / 置换检验 | 信号本身是否强于"同一时段、同一动量条件下的随机入场" |
| Walk-forward | 表现是否集中在某个时间段、是否依赖特定 regime |
| 参数平台检测 | "孤峰"——可信的最优参数应该坐落在一片平台上，四周同样好 |

### 关键区分：selection-aware vs selection-blind

这是整套方法论里最值钱的一句话：

> bootstrap、walk-forward、placebo 都是 **selection-blind** 的——从 300 组配置里挑出来的冠军曲线，照样能骗过它们。**只有 DSR 和 PBO 知道你摇了多少次骰子。**

所以流程上的硬规则是：**DSR 或 PBO 不过，一票否决，不看曲线多漂亮**。很多地方所谓"验证过"的策略，差的就是这一步。

## 三、多重检验的记账方式，比检验本身更容易出错

### 3.1 n_trials 要算"整个项目"，不是"这一次脚本"

块自助可以告诉你"这个 edge 不是运气"（P(Sharpe≤0) 很低），但如果把整个研究周期里试过的**几百组**参数都算进 DSR 的 n_trials，DSR 会大幅低于表面数字。隐藏成本是整个研究项目的搜索历史，不是当前这一个脚本跑了几组。

### 3.2 但反过来，n_trials 也经常被算得过大

一个**固定公式**（没有被网格搜索选出来的、事先写死的规则）对应的 n_trials 是 1，不是你这个项目里跑过的配置总数。我们踩过这个坑：连续几天把一个固定公式按"网格搜索"记账（n_trials 取 18、30），得出"过拟合"的结论；修正为 n_trials=1 之后，同一条收益序列直接通过。

**结论：n_trials 不是一个可以"保守一点总没错"的旋钮。** 算大了会误杀固定规则，算小了会放过数据挖掘。正确做法是诚实地回答"这个具体的参数组合，是从多少个候选里被选出来的"。作为纪律，应该在跑检验之前就把 n_trials 敏感性扫一遍（比如 1 / 5 / 20 / 100 / 200），看结论在哪个区间翻转。

### 3.3 trial 之间高度相关时，标准 DSR 会算错惩罚

标准 DSR 假设所有 trial 互相独立。但实际研究里，同一个信号 × 多个回看窗口 × 多个标的，这些 trial 在同一个市场 regime 下高度相关（实测某批 trial 的日收益相关矩阵，平均非对角相关系数在 0.3 量级）。

把 120 个高度相关的 trial 当成 120 次独立检验，会有**两个方向同时存在的偏差**：

- 高估多重检验惩罚（对真信号太苛刻）；
- 同时低估"这些 trial 其实是同质化失败，不构成 120 次真实独立否证"这个共享 regime 风险。

所以"保守 = 安全"在这里不成立。改进做法是先测 trial 收益的相关矩阵，把 apparent n_trials 收缩成 **effective n_trials**：

- **IPR（Inverse Participation Ratio）**：基于相关矩阵特征值分布；
- **Marchenko-Pastur signal clipping**：随机矩阵理论，把噪声特征值和信号特征值分开。

实测中这个修正可以把 n_eff 从 120 收缩到个位数，DSR 数值成倍变化。**要强调的是：修正的目的不是把不合格的结果救活**（我们实测的那个案例，修正前后都是失败），而是让判决建立在正确的检验次数上。

## 四、特征级检验和策略级检验是互补的，不是重复的

主流反过拟合工具（DSR/PBO/bootstrap/walk-forward）全部是**策略级**的：输入是一条完整的收益率序列，隐含了"入场规则 + 出场规则 + 仓位"。

还缺一层**特征级**检验：这个指标本身到底有没有预测力，不涉及任何交易规则。典型做法是 Spearman IC + 非重叠采样 + 分块 IC-IR 稳定性检验。

正确的流水线是：

```
特征级 IC 筛选  →  形成交易规则  →  策略级反过拟合验收
（筛掉没有预测力的指标）      （筛掉过拟合的规则）
```

跳过第一步直接做策略级验证，会浪费大量算力在根本没有信息含量的特征上；只做第一步不做第二步，则会把"IC 显著"误当成"可交易"。

## 五、参数平台，不是参数尖峰

全量网格搜索得到的"最优"，必须看它是不是一整片高原。

- 可信的形态：一大片相邻参数组合整体落在同一个良好区间里；
- 不可信的形态：一个孤立尖峰，隔壁参数立刻塌掉。

**极端参数敏感性本身就是警示信号**，等价于"这个结果是被噪声选中的"。反过来，如果一个结果被质疑，"周围一片参数都同样好"是最有说服力的辩护证据之一。

---

## 六、不要重复造验证工具

我们在不同项目里至少三次独立手写过 DSR/PBO/CPCV/Holm 校正的实现，每次都比上一次更简陋（赶时间时往往只实现 DSR 一项，PBO、bootstrap、placebo、参数平台全部省略）。

教训很直接：**验证工具是基础设施，应该沉淀成一个包被调用，而不是每个研究项目现场重写一遍**。两套独立实现同时存在时，也应该主动对比是否一致，而不是任由它们分叉。同理，meta-labeling / triple-barrier 这类经典方法，在动手实现之前应该先确认现有代码库里是不是已经有了。

---

## 七、一句话总结

> 回测的默认判决是"过拟合"。检验流程的作用不是证明策略有效，而是**尽最大努力杀死它**；活下来的那个，才配进入下一关——而下一关不是实盘，是最近一段时间的前向观察（见《研究纪律检查清单》）。
