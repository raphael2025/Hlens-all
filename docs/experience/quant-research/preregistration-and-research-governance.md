# 预注册、评审闸与研究治理

这份文档讲的不是统计方法，而是**流程**：在跑任何实验之前先把什么写死，谁有权把一个结论从"提案"升级成"已验证"，以及失败的实验该怎么存档。

动机很简单：反过拟合的统计工具（DSR / PBO / walk-forward）都假设你**诚实地报告了自己试了多少次、事后没有改口径**。这个假设不是自动成立的，它必须由流程来保证。没有流程时，一个研究者会在看到结果之后无意识地微调口径、重开"同义实验"、把失败的那一支从记录里悄悄删掉——而所有这些动作，统计检验都看不见。

---

## 一、预注册文书：跑之前就要冻结的东西

我们在每一条研究路线开跑前写一份 prereg 文档并提交，文档里至少要有下面八项。**冻结之后不允许改**——改了就降级为探索性研究。

| # | 栏目 | 为什么 |
|---|------|--------|
| 1 | 冻结日期 + 装置（数据源、成本口径、成交时点、最大持仓期） | 让"用了什么口径"不可事后协商 |
| 2 | 假设陈述 **+ 结论上限** | 见下节，这是最重要的一条 |
| 3 | 冻结的结构定义 | 哪些东西不参与搜索、复用哪条已有路线的定义 |
| 4 | 搜索空间与预算（确切的配置数、抽样种子） | 多重检验的分母必须是事先写死的数字 |
| 5 | 窗口划分，并标注哪些窗口已被污染 | 见下节 |
| 6 | 指标、阈值、相对改进要求、功效下限 | 防止事后挑一个刚好通过的指标 |
| 7 | 裁决与杀死条件 | 什么情况下这条路线直接死掉、禁止改名重开 |
| 8 | 归档与不可变证明 | 见第四节 |

### 1.1 "结论上限"：先写死这次实验最多能证明什么

这是我们用过最有价值的一条约定。在假设旁边直接写一句：**无论结果多好，这次实验的结论最多只能写成什么。**

典型场景：某个市场在可得历史里只包含两个完整的下跌周期。那么关于"下跌周期里该怎么做"的任何检验，无论 p 值多小，结论上限都是"两个窗口的证据、低功效"，**禁止写成"已验证"**。

这条约定的作用是在情绪最容易失控的时刻（结果很漂亮的时刻）提前设好刹车。它比事后的谦虚有效得多，因为它是在你还不知道结果的时候写的。

### 1.2 提出假设的窗口 = 污染窗口

如果一个假设是**因为看到某段数据才被想出来的**，那段数据就不再是这个假设的检验窗口。它可以作为"诊断窗口"展示，但在上面取得的改善必须降级，不能计入裁决。

实践中要在 prereg 里逐个窗口标注：训练内参考 / 选参窗 / 污染诊断窗 / 真正的验收窗。四类窗口的结论权重完全不同。

### 1.3 功效不足 = "不可判定"，不是"通过"

预先写死每个关键口径的最小样本数（例如完整往返次数 N ≥ 某个门槛）。达不到时的判决是**"不可判定，维持现状"**，而不是"点估计为正，倾向通过"。

这条看起来显然，但在实际研究里几乎总被违反：一条路线跑出 7 笔交易、点估计漂亮，作者会本能地写"初步证据支持"。它不是证据，它是噪声。

## 二、评审闸：把实现停在实验之前

我们做过一次最有效的干预，是在第一轮实现完成、实验尚未开跑时，**强行插入一次独立评审，并允许评审给出"阻塞"结论**。那次评审列出 4 条阻塞项和 5 条必查项，实验被整体推迟到全部阻塞项都有**通过的回归测试**之后才开跑。

评审闸文档的写法：

- 每条阻塞项写清楚：**现在的代码做了什么**、**正确流程应该是什么（分步骤）**、**需要补什么测试来证明已经修好**；
- "必查项"与"阻塞项"分开列，必查项不阻塞开跑但必须有人签字确认；
- 最后一句必须是硬约束，例如"在这些阻塞项有通过的测试之前，不得启动第一轮实验"。

典型的阻塞项类别（每一条都对应我们真实踩过的坑）：

1. **验证集 refit 泄漏** —— 用于选阈值的验证集预测，必须来自只在训练段拟合的模型；先在 train+val 上重拟合再算验证表现，等于让验证集部分变成样本内。
2. **折末强制平仓的成本没记** —— 每个测试折必须以空仓结束并支付最后一次仓位变动的成本。
3. **头条指标的聚合方式** —— 主指标必须由**拼接起来的、不重叠的样本外收益序列**算出，而不是各折 Sharpe 取平均。折均值只能作为次级诊断。
4. **交易指标的口径** —— bar 级胜率/盈亏比 ≠ 完整往返的胜率/盈亏比。头条数字必须用完整往返，反手要拆成"平仓 + 新开仓"两笔。
5. **purge 覆盖** —— 训练/验证、验证/测试两个边界都要检查隔离带是否覆盖了前瞻标签的完整期限。
6. **试验计数** —— 所有配置、所有阈值候选都要计入多重检验的分母。
7. **失败要被记录** —— 某个模型族全部候选失败时必须显式记录失败，不允许静默跳过后回退到第一个配置。

评审闸的产物应该直接变成测试文件名（我们真的有 `test_review_blockers.py` 和 `test_protocol.py` 这种文件）：**把研究纪律写成测试，是唯一能在几个月后仍然生效的写法。**

## 三、证据状态词汇表：别让"设计"冒充"现状"

文档密集的项目有一个特有的失败模式：一份写得很好的设计文档，被后来者（尤其是 AI 编码代理）读成"这个功能已经存在了"。防御手段是给每条结论强制标注证据等级：

```
CONFIRMED_BY_CODE     代码里确实这么写的
CONFIRMED_BY_TEST     有具名测试覆盖
CONFIRMED_BY_ARTIFACT 有归档的实测产物
DOCUMENTED_ONLY       只有文档这么说
PROPOSED              提案，尚未被接受
CONTRADICTED          有证据反驳
UNKNOWN               没查过
```

> **文档声明不是实现证据；设计可行性不是当前能力。**

### 3.1 两条互不相干的状态轴

更进一步的一个发现：**"数据拿不拿得到"和"组件有没有实现"必须是两条独立的轴**，混用会制造"数据能拿到 ≈ 系统已就绪"的错觉。

- 轴 A（组件实现）：`SPECIFIED` → `PARTIAL` → `IMPLEMENTED` → `VERIFIED`
- 轴 B（数据源探测）：`PROBED` / `PARTIALLY_PROBED` / `BLOCKED` / `UNAVAILABLE`

轴 B 全绿不改变"轴 A 零代码"这一事实。我们的状态表里专门写了这句话，因为它被误读过。

注意 `BLOCKED` 与 `UNAVAILABLE` 的区别也要守住：前者是"因为我们自己设的范围约束（例如不使用凭据）而拿不到"，后者是"这个能力不存在"。**"这次没测到"绝不能记成 `UNAVAILABLE`**——那是把无知写成了知识。

### 3.2 状态迁移规则

1. 状态只能凭证据前进：没有归档证据不得标 `VERIFIED`，没有代码不得标 `IMPLEMENTED`。
2. **`VERIFIED` 会过期**：每行声明自己的复验周期，超期自动降级。
3. **规格变更自动降级**：被引用的条款一变，相关组件从 `VERIFIED` / `IMPLEMENTED` 降为 `PARTIAL`。
4. `PARTIAL` 必须逐条列出缺什么——"部分完成"而不说缺什么等于没有状态。
5. 状态更新与代码变更同一次提交，不得滞后。

### 3.3 决策登记册

把"已经定了的"和"还没定的"分开登记，每条决策带一个状态和一条**验收闸**：

- `ACTIVE`：已由明确决定确立
- `PROPOSED`：推荐基线，但还不是实现契约
- `PENDING_EVIDENCE`：需要某个具名的探测/测试/实测观察
- `PENDING_OWNER`：需要一次明确的范围选择
- `REJECTED`：明确排除在当前阶段之外

配套一条硬规则：**`PENDING_*` 一律视为不可实现**。实现可以开始的前提是把所有相关条目逐条解掉，并在文档里写出"实现闸"清单。

这里还有一条很实际的经验：**不要在多份文档里复用裸的短 ID**（`A-01`、`C-07` 这类）。跨文档引用必须写成"文件 + 章节 + 本地 ID"，否则一个裸 ID 在半年后会指向错误的文档。

## 四、不可变证明与归档

预注册如果可以事后偷偷改，那它一文不值。我们用的证明方式很土但有效：

> 裁决文档里写死一句：`git diff <prereg_commit>..HEAD -- <prereg文件>` 必须无输出，否则本次结论自动降级为探索性。

其他配套约定：

- 全部候选配置、全部内层评分、全部失败记录、最终选中的参数、全部对照路径**都要归档**，不只归档赢家；
- 未被选中的候选**不得**事后单独拿去跑验收窗来制造排名；
- 查看验收窗的次数有上限，并且每次查看前要追加到运行日志里（把"我看了几次 holdout"这件事本身变成可审计的记录）。

## 五、负结果归档

失败的实验是资产，但只有被**结构化保存**时才是。我们的约定是：

**目录**：一个专门的 `negative-results/`，每个失败假设一页，文件名 `YYYYMMDD-短名.md`。

**必填头**：

```
experiment_id:
git_commit:
data_snapshot_id:
cost_model_version:
result: negative
```

**正文最少五段**：

1. 假设，以及当初为什么值得一试；
2. 设计（宇宙、切分、对照臂）；
3. 主指标与对照的差距；
4. **失败原因归类**：泄漏 / 过拟合 / 成本 / 非平稳 / 实现 bug / 功效不足；
5. **是否禁止再开同义实验**（是/否 + 冷却期，例如"裸动量费后"冷却 30 天，只允许带新增制度过滤或新样本的增量实验）。

**与正结果同等地位**：周复盘必须点名本周的负结果。丢弃负结果直接在可复现评分卡上失分。

第 4 项（失败归类）是这套模板里最值钱的部分。"没跑通"和"跑通了但没边"是完全不同的两件事，不归类就无法积累。

## 六、可复现评分卡

上线/评审前的自检表，每项 0–2 分（0 无 / 1 部分 / 2 完备），满分 24：

| # | 项 | 满分（2 分）的标准 |
|---|----|----|
| 1 | 数据版本哈希 / 快照 ID | 强制 |
| 2 | Point-in-time 宇宙与特征 | 全覆盖 |
| 3 | 代码 commit 绑定结果 | CI 自动 |
| 4 | 随机种子与环境锁定 | lockfile + 容器镜像 digest |
| 5 | 成本 / 冲击假设显式 | 分品种模型（而非一个全局 bps） |
| 6 | 训练 / 验证 / holdout 隔离 | purged + 终局 holdout |
| 7 | 试验次数记账（多重检验） | 全记录 + DSR |
| 8 | 事件时钟与时区测试 | 契约测试 |
| 9 | 纸面 vs 实盘差距报告 | 定期 + 门槛 |
| 10 | TCA / 母单对齐 | 全生命周期 |
| 11 | 配置变更审计 | 不可变 + 审批 |
| 12 | 失败与负结果存档 | 强制保留 |

建议门槛：**研究分享 ≥ 12；实盘候选 ≥ 18；资金放大 ≥ 22。**

配套的种子与环境约定：所有随机过程（CV 打乱、bootstrap、初始化）都记录 seed，多 seed 时至少报告中位数**与最差 seed**；没有 lockfile 的数值结果一律标记为"不可复现草稿"。

## 七、质量熔断（Stop-the-Line）

产出量服从质量。命中以下任一条件时**暂停新主题扩写**，先修复：

| 条件 | 动作 |
|------|------|
| 互链缺失率相对基线明显上升 | 停扩写，跑链接检查并修复 |
| 发现文档含疑似密钥/密码 | 立即删除痕迹、轮换密钥、复盘流程为什么没拦住 |
| 同主题结论互相矛盾且未标注争议 | 合并，或加"争议"框后再继续 |
| 连续多篇缺结构（无定义/无坑/无延伸） | 回炉模板，抽检最近 20 篇 |
| 可复现评分卡主栈 < 12 | 只写工程文档，不写新异象 |

## 八、写作与引用规范（知识库侧）

如果研究产出会沉淀成知识库，还需要几条内容规范，否则库会退化成一堆名词解释：

- **每篇正文必须同时有"构成 / 原理 / 经验"三段**。构成 = 由哪些可复制的零件拼出来（公式、状态机、数据字段、时点、约束）；原理 = 为什么这样拼会赚钱或会亏（谁付钱、什么风险补偿、什么制度摩擦），"历史上涨过"不算原理；经验 = 公开可核的样本外/事故/容量/失败模式，**以及停用规则**。缺任何一条 = 未完成。
- **经验必须可证伪**，禁止把营销材料里的夏普当成本库结果；文献结论与自有回测结果必须分栏写，未回测的不得冒充自有结果。
- **引用只放公开摘要、作者、年份、出处、DOI/链接 + 一句"我们采用了什么 / 没采用什么"**；禁止粘贴付费墙全文、禁止整体转载未授权数据集。
- **密码与密钥不入库**，并且配一个自动化检查（我们有一个 pytest 用正则扫样本里的 `api_key|secret|password|token` 模式，不通过就不允许入库）。

## 九、一句话

> 统计检验能判断"这条收益曲线是不是运气"，但只有流程能保证"你给统计检验看的是真实的试验历史"。预注册、评审闸、证据等级和负结果归档不产生 alpha——它们产生的是**你有资格相信自己结论**的那部分底气。
