# Point-in-Time 数据契约与泄漏面清点

这份文档从**数据与管道**的角度清点前视偏差：每一处泄漏发生在流水线的哪一步、用什么结构性手段堵死、以及怎么用测试证明它被堵死了。

统计检验抓不住泄漏。一条被污染的收益序列送进 DSR/PBO，得到的只是"这个被污染的结果不像是运气"——完全正确，也完全没用。泄漏只能在数据层和代码层解决。

> 核心原则：**任意时刻 $t$ 的特征，只能由"在 $t$ 时刻实际可得"的记录构造出来。** 这条约束必须同时施加于三个环节——特征构造、shift/lag 对齐、标签生成。少施加一处就全线失效。

---

## 一、实盘侧最常见的泄漏：仍在形成的那根 bar

在实时系统里，最高频发生的前视不是"用了明天的收盘价"，而是**用了当前这根还没收盘的 K 线**。

形成中的 bar 的 high/low/close 还在变。用它算信号意味着：

1. 你用了决策时刻并不存在的数据；
2. 事后**无法复现**——同一时刻再跑一次，数字已经不同了。

结构性的解法是在数据源和信号之间插一个不可绕过的环节，把仍在形成的那一根直接丢掉（我们叫它 `drop_forming()`）。数据源接口只输出**已收盘**的 bar，信号层根本没有机会看到形成中的那根。

**这是把纪律变成类型的典型例子**：不是在文档里写"记得用已收盘 bar"，而是让"拿到形成中的 bar"这件事在管道里不可表达。

---

## 二、验证集 refit 泄漏

这一条隐蔽到需要专门画出正确顺序才能讲清楚。

**错误流程**（我们的第一版实现就是这样）：在训练段拟合 → 预测验证段 → **在 train+val 上重新拟合** → 用重拟合后的模型算验证表现 → 据此选配置和阈值。

问题在倒数第二步：用来做选择的那个"验证表现"，已经部分是样本内了。

**正确流程**：

1. 只在训练段拟合；
2. 预测验证段；
3. 在验证段上选配置和无交易阈值；
4. **冻结**这些选择；
5. 在 train+val 上重新拟合；
6. 预测封存的测试段。

对应的回归测试写法：**在训练完成之后修改验证段的标签，验证段的预测值必须完全不变**（阈值选择那一步是显式分离的例外）。这个测试能自动抓住任何把验证标签偷偷带进拟合的改动。

## 三、切分之前做的事情，都要重新审一遍

`dropna()` 本身不引入未来信息，但它发生在切分之前时会制造两类问题：

- **尾部行被系统性删除**：前瞻收益标签（`shift(-h)` 得到的）在序列末尾必然是 NaN，整行被 drop。于是**最近的 h 根 bar 永远不在训练集里**。
- **训练与实盘口径分叉**：如果实盘脚本复用了同一份"特征构造 + dropna"逻辑，实盘也会拒绝使用最新的 h 根数据——而实盘根本不需要前瞻标签。

修法是把"训练用的 target"和"实盘用的 feature"拆开：实盘路径不得因为 `ret_fwd_*` 为 NaN 而丢行。

同类问题还有：标准化 / PCA / 中性化的参数在**含未来的全样本**上拟合再应用到历史。这是训练管道里最隐蔽的一处，必须只在训练窗内 fit。任何 `expanding()` 统计量在特征工程中应当直接禁用——它让当前 bar 知道整段历史（含未来）的分布。

---

## 四、预热窗口必须显式留出，而且不足时要报错

回看算子需要历史，滚动 z-score 需要更多历史。报告窗口之前必须留出两段预热：

```
[ 算子最大回看 ][ 归一化预热 ][ ←—— 报告 / 交易窗口 ——→ ]
```

关键的工程决定是：**历史不足时直接报错并给出最早可用起点，而不是静默把窗口往后挪。**

静默平移是个很恶劣的失败模式——它让每一折"悄悄地丢掉开头的 N 根 bar"，而且因为没有报错，没人会去检查。我们在一份复盘里确认过：一个早期版本正是因为每个窗口静默丢掉开头的指标预热段，系统性低估了自己某一年的测试收益。

对应到折切分上，每个窗口都要显式声明自己的"指标跑道"（runway），并写一个断言确保这段跑道确实在窗口起点之前。

---

## 五、purge / embargo 的覆盖必须逐个边界检查

隔离带不是加在"训练/测试"之间就完事了。三段式切分有**两个**边界（train/val 和 val/test），两个都要检查：隔离带宽度 ≥ 前瞻标签的完整期限。

一条反向的观察也值得记下来：我们有一条研究路线在 v2 重构时把"标签"整个删掉了——研究对象从"预测方向"改成"一组布尔条件是否满足"。副作用是**泄漏面随标签一起消失了**：条件在 bar $i$ 上只读 $\le i$ 的数据，折边界在 bar 收盘处是干净的，不再需要 purge/embargo。

> 减少泄漏最彻底的办法有时不是加检查，而是**换一个没有那个泄漏面的研究对象**。

---

## 六、实盘与回测必须共用同一段代码，并用测试钉住数值相等

我们实盘路径的做法是：把内存里的 K 线直接构造成回测用的同一种数据结构，然后交给**回测用的同一个求值函数**。单元测试逐点断言两条路径的输出相等（实测差异在 4e-13 量级，即浮点噪声）。

这个测试有一个不太直观但很重要的第二作用：**它同时是一个前视检查**。实时路径在结构上看不到未来（未来的数据还不存在）。如果离线路径给出完全相同的数字，那么离线路径也没有偷看未来。

反面案例同样真实：回测与实盘各写一份信号代码，长期跑下来才发现两边的回看窗口对应的 bar 数根本不同——"回测验证过"的东西和"线上在跑"的东西不是同一个策略。

## 七、数据源对账：同一个名字不代表同一根 bar

这一条是真实踩到的，而且很容易漏。

上线前我们写了一个 `check_feed_consistency()`，拿实时数据源和训练数据在**重叠区间**逐根比对。结果发现：某第三方行情源的日线**边界在 03:00 UTC**，而训练数据的日线边界在 00:00 UTC。收盘价最大偏差达到 7.4e-3 量级——**大于这些因子声称的任何 edge**。

换句话说：直接接上那个数据源，因子看到的根本不是训练时的那根 bar。

配套的工程约定：

- 对账是**上线前的强制步骤**，不是可选诊断；
- 对账不通过时命令行返回**非零退出码**（我们用退出码 3），实时信号同时带 warning；
- 对账覆盖的不只是数值，还包括时区、bar 边界、复权口径、字段命名。

更一般的表述：**跨数据源合并之前，必须核对复权方法论、时钟基准和边界定义是否一致**，不同供应商在这几项上从来不一致。

## 八、Point-in-time 的经典面（非加密市场同样适用）

这些是公开文献里反复出现、我们在笔记里锚定过来源的经典坑，列在这里作为清单：

- **披露滞后**：基本面/财务类特征必须按"实际可得日期"对齐，不能用会计期末日。公开研究里测到的中位滞后在 40 天量级，忽略它可让某些因子的 IC 接近翻倍虚高。
- **修订版本**：分析师预期、财务重述等数据有多个版本。必须取"发布时间戳 ≤ $t$"的那个版本，不能用事后修订的最终值。
- **后复权 = 把未来编码进历史**：以最新日期为基准向前调整历史价格，会让 $t$ 时刻的"调整后价格"成为 $t$ 之后所有公司行为的函数。信号层用前复权，记账层用未复权价 + 显式的公司行为表。
- **宇宙随时间变化**：用"今天的成分股/今天还在交易的币"回填历史，是前视偏差与存活偏差的叠加。退市/下架标的应当**打标而不是删除**（保留完整历史 + `delisted_at` 字段），回测引擎遇到下架日要强制平仓并记录隐含成本，而不是静默清零。
- **加密市场的"公司行为"**：合约下架、季度合约交割换月、永续乘数变更、项目分叉改名、最小名义价值与价格精度变更。处理不当会产生与股票"未复权"同类的价格跳变 artifact。实体 ID 要稳定，符号可以变。
- **重叠采样**：多日前瞻收益按日采样会产生高度自相关的 IC 序列，直接按独立样本算 t 统计量会系统性高估显著性。

## 九、检查清单

跑任何实验之前逐项打勾：

- [ ] 信号只使用已收盘的 bar；形成中的 bar 在管道层被丢弃，不依赖调用方自觉
- [ ] 归一化 / PCA / 中性化只在训练窗内拟合；全样本或 expanding 统计量为零
- [ ] 用于选择的验证集预测来自**只在训练段拟合**的模型；有回归测试钉住
- [ ] 切分前的任何行级过滤（dropna 等）都审过一遍，确认没有系统性删除尾部
- [ ] 每个窗口显式声明预热段；历史不足时报错而不是静默平移
- [ ] train/val 与 val/test **两个**边界的隔离带都覆盖前瞻期限
- [ ] 实盘与回测共用同一个求值函数；有逐点数值相等的测试
- [ ] 上线前跑数据源对账；不通过返回非零退出码
- [ ] 所有时间戳有明确的时区和 bar 边界定义，并且跨数据源核对过
- [ ] 前瞻收益的采样是非重叠的，或者显著性检验做了自相关调整
- [ ] 拿不准某个时点信息是否可得时，做一次"再滞后一期"的压力测试——表现剧烈恶化说明原信号严重依赖前视
