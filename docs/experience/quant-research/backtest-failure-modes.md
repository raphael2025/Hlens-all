# 回测失效模式目录：真实踩过的坑

上一份文档讲的是"应该跑哪些检验"。这一份讲的是**检验之外的东西——代码 bug、口径漂移、结构性幻觉**。这些坑的共同特点是：它们不会被 DSR/PBO 抓住，因为进入统计检验的那条收益率序列本身就是错的。

每一条都对应真实发生过的事故，不是教科书上的假设。

---

## 一、前视偏差的隐蔽变体

### 1.1 expanding 统计量（永久禁用）

用 expanding mean / expanding z-score 做标准化，等于让当前这根 bar 知道整段历史（包括未来）的分布。这是最容易犯、后果最夸张的一种前视偏差：一个短周期反向信号曾经因此显示出极高的正 Sharpe，改成 rolling window（至少 1 天）之后，真实结果是**深度负值**——不是"变弱"，是**符号反转**。

**规则：所有标准化、分位数、阈值，一律 rolling window；任何训练集级别的 expanding 统计量在特征工程中禁用。**

### 1.2 标注时点与确认时点不一致

形态类、结构类信号最容易犯：一个摆动高点/低点、一个"破前高不破前低"的结构，往往要等若干根 bar 之后才能确认。信号必须打在**确认**的那根 bar 上，不能打在**起源**的那根。

### 1.3 重叠采样导致 t 检验虚高

用滚动窗口算前瞻收益率时，相邻样本高度重叠，有效样本量远小于名义样本量，t 统计量会被严重放大。我们的特征评估框架最早就踩过这个：修正成非重叠采样之后，p 值从"全部显著"变成"大部分不显著"。

## 二、成本与执行侧的事故

### 2.1 成本方向算反

一次独立审计发现，某条"证据最强"的腿，原始回测把交易成本的符号算反了，伪造出接近 100% 的胜率；修正之后是干净的净亏损。这个 bug 还顺便解释了另一个长期悬而未决的矛盾（同一策略在不同数据库上结论相反）。

**规则：任何"异常漂亮"的胜率（尤其接近 100%）默认当成 bug 处理，先去查成本、方向、标签对齐，再谈信号。**

### 2.2 成交模型的乐观/悲观偏差

同一条策略，换一个成交模型结果可以从明显为正翻到明显为负：

- 初版 maker 模型用 taker 平仓 → 大幅负偏；
- 校准后的 maker 模型（ask 入、bid maker 出）→ 与 mid-hold 基准一致。

**规则：每一个 walk-forward 窗口都要附带一个统一口径的对照基准（例如 mid-hold）；不要用一个未经校准的执行模型去"否定"一条信号，也不要用它去"证明"一条信号。**

### 2.3 特征仓库的伪标签不能当 PnL 真理

为了快速筛因子而预计算的 forward-return 标签（parquet 里的 `fut_*` 之类）只能用于筛选特征相对强弱，**不能用来出最终 PnL**。真理来自事件驱动的重放 + 带真实成本的撮合仿真。

### 2.4 合成数据上的胜率完全不可信

一组订单流/微观结构类 alpha 在**合成数据**上测出接近 100% 胜率，在**真实历史重放**上全部失败（胜率掉到远低于含手续费的盈亏平衡线）。

> 合成数据的 100% 胜率是生成器的统计假象，不是市场规律。

合成数据只能用来测代码逻辑（会不会崩、边界条件对不对），**不能用来评估策略是否有效**。

## 三、结构性幻觉：数字是真的，含义是假的

### 3.1 固定 TP/SL 下的"盈亏比"

当止盈止损写死为固定的 R 倍数（例如 TP=2R / SL=1R）时，盈亏比会恒定在某个数值附近，**与行情无关**。它看起来像一个业绩指标，其实是一个参数的机械后果。这类策略的命脉是胜率，不是盈亏比。

同理，小样本（十几笔）的盈利因子（profit factor）纯粹是噪声，不构成证据。

### 3.2 样本太小导致的 Sharpe 爆表

几笔交易也能算出一个极高（甚至上百）的 Sharpe。**任何低于最小笔数门槛的场景，指标一律不予解读**——不是"打折采信"，是"不解读"。

### 3.3 Sharpe 要拆开看 mean 和 std

如果分母（波动率）明显低于市场基准，高 Sharpe 可能只是"几乎不动"，而不是"稳定赚钱"。拆开看分子分母是判断 Sharpe 真假的第一步。

### 3.4 收益高度集中 = regime 巧合

如果全部盈利来自少数几天/一个月，而其余时间净负，那就不是 edge，是撞上了一段特定行情。经验阈值：**如果超过 30% 的交易（或收益）集中在整个样本期不到十分之一的时间窗口内，默认按 regime 巧合处理，并主动去反证。**

### 3.5 全历史 deflate 会被早期 regime "喂饱"

一个策略可以同时满足：全历史 DSR/PBO/walk-forward 全部通过，**而最近一年、最近半年是负的**。原因是早期某一段极端行情贡献了绝大部分收益，把全样本统计量撑了起来。

这是我们见过**最常见、最危险**的失败模式，在至少三个互相独立的项目里各自出现过一次。对应的补救措施见《研究纪律检查清单》里的"近期窗口单独设闸"。

### 3.6 权益路径依赖：margin call 会摧毁纸面 Sharpe

一个在"无爆仓约束"假设下表现优秀的组合，加上真实的维持保证金强平逻辑之后可能直接崩塌：权益曲线长期贴近零、频繁触发强制平仓，Sharpe 从优秀掉到接近零。

> 纸面 Sharpe 是**收益序列**的性质；能不能活下来是**权益路径**的性质。两者不是一回事。

**规则：任何带杠杆的组合，回测引擎必须显式实现维持保证金强平，并报告强平次数。强平次数不为零就说明这个配置不可部署，不管 Sharpe 多好看。**

## 四、口径漂移与复现事故

### 4.1 回测口径和实盘口径不一致

真实事故：某个"12 个月动量"信号，回测里用的 bar 数其实只对应一个多月，而实盘脚本用的是真正 12 个月。于是"回测验证过"的东西和"线上在跑"的东西根本不是同一个策略，连续多天的结论建立在错误前提上。

**规则：回测与实盘必须共用同一份信号计算代码（同一个函数，同一份参数配置），不允许两边各写一份。**

### 4.2 复现脚本本身有 bug

复现他人——**甚至自己**——的策略时必须逐行审计。曾经因为一行多余的赋值语句，把一个真实亏损严重的策略算成了荒谬的天文数字正收益。

**规则：复现结果必须逐行 diff 原始逻辑；自己写的复现脚本不享有可信度豁免。**

### 4.3 子 agent / 协作者报告的结果必须自己复现一遍

多 agent 交叉验证流程里，有子 agent 报告过多年期的优秀 Sharpe，主流程复现后发现结果完全失真。

**规则：任何来自另一个执行者（人或 agent）的结论，在被写进结论库之前必须由主流程独立复现。审阅类工具只能核对机械事实，无法验证语义断言。**

### 4.4 "复现不出来"比"测出无效"更严重

一个历史上报告过明显正收益的版本，过一段时间用同样的方法论在当前数据上重跑，结果是负的，**完全无法复现**。

诱惑是把它归因为"市场变了"。更可能的真相是：**当初那个正结果本身就有问题**（过拟合到某个特定数据快照、数据管道有偷价、或者上游数据源已经 stale）。

**规则：任何"历史上验证过有效"的结论，如果找不到可复现的完整记录（代码 + 数据快照 + 参数 + 环境），一律打问号，不得作为后续决策的依据。**

## 五、"0 结果"先怀疑管道，再怀疑因子

一条事件研究路线一度显示"0 行数据 / 0 个信号"，第一反应是判因子死刑；后来发现是数据 loader 的对齐 bug，修复后重测才是真正有意义的证伪。

**规则：0 事件 / 0 信号 / 全 NaN，默认是管道 bug 而不是结论。先做数据完整性自检，再谈因子有效性。** 同理，信号频率异常高（例如全样本超过一半的时间都在发信号）也应触发"伪策略"告警。

---

## 六、加过滤条件 ≠ 加 edge

一个直觉很强但被反复证伪的做法：给一个有效信号叠加"更聪明"的二次过滤（流动性过滤、情绪过滤、多周期确认）。

实测结果是**普遍变差**：

- 某截面动量单独测时，多数 walk-forward 窗口为正；叠加一个流动性过滤因子之后，绝大多数窗口翻负。
- 在一个多策略框架里，把"聪明钱"信号叠加在技术信号上，结果没有改善，甚至更差。
- 精细化执行（等回调入场、阻力位止盈、多周期精细组合）系统性地不如"趋势确认后直接进场"——原因是最强的趋势往往不给回调机会，等回调等于踏空或追高。

**规则：二次因子融合默认会破坏原始 alpha。任何"加一层过滤"的改动，必须和未加过滤的基线在同一套 walk-forward 口径下对比，而不是只看加过滤之后的绝对表现。**

---

## 七、"ROBUST" 不能泛化到"类似的变体"

同一个算法，只是换一下回看窗口 / 调仓频率 / 持仓数量，结果可以从"验证通过"直接变成"彻底失败"。

**规则：验证结论只对被验证的那个确切参数组合成立。要用变体，就得重新跑完整验收流程，"照着改良一下"不算。** 另外，复现一个宣称通过的结论时，要逐行确认它确实做了它声称做的事——我们审计过一个"截面动量"，实际实现其实是单标的时序动量，而且某个参数是死参数（导致多重检验次数被虚增）。
