# 搜索目标函数的设计：当优化器"在工作"却只是在过拟合

这份文档讲一类特定的失败：**参数/规则搜索在选择期表现优异，而样本外更差**——不是"改善幅度缩水"，是**方向反转**。

它值得单独成文，因为它长得不像过拟合。所有防御机制看起来都在工作：有 walk-forward、有多折、有收缩惩罚、有复杂度惩罚、有回撤上限。优化曲线漂亮地上升。然后在唯一没被优化过的窗口上，排名越高的候选表现越差。

---

## 一、诊断：先测目标函数本身能不能预测样本外

在解释任何搜索结果之前，先做这一件事：

> 取若干个候选（不只是冠军），同时算出它们的**选择期得分**和**样本外表现**，做秩相关。

我们跑过一次：数百个候选，Spearman 秩相关约 **−0.4**。不是弱相关，是**单调地指向错误方向**——选择期得分的最高十分位，样本外表现最差。

这个诊断非常便宜（选择期的得分本来就算过了，只需要额外在 holdout 上跑一遍全部候选），而且它回答的是一个比"冠军好不好"重要得多的问题：**这个目标函数到底有没有资格做选择。**

注意做这个诊断时要区分种群来源：如果搜索包含进化阶段，那么进化出来的种群里全是"兄弟"，它们的富集度测的是**血缘**而不是**优劣**。秩相关和任何富集度统计都应该在**无偏的随机采样阶段**单独算一遍。

---

## 二、根因通常是折的信息量，不是搜索算法

我们那次的根因查出来是这样的：

六个 walk-forward 测试折里，**有三个折完全没有交易**。策略的趋势包络在下跌和震荡行情里正确地保持空仓——这本身是设计意图——但一个零交易的折贡献一个恒定的 0，**不区分任何候选**。

于是目标函数实际上由**三个上涨折、总共七笔完整往返**决定。而它真正在度量的东西是"这个候选吃了多少上涨行情的暴露"——这恰好与"能否在下跌期活下来"反相关，而后者正是 holdout 在测的东西。

> 用八千个候选去拟合七笔交易，从一开始就不可能成立。反 Goodhart 机械（样本量收缩、离散度惩罚、train-test gap 惩罚、复杂度成本、回撤上限）只能延缓它，救不了它——**缺陷在折的信息含量，不在折的聚合方式。**

### 2.1 补救方向（按性价比排序）

1. **增加有效交易数，而不是增加搜索强度。** 把同一套搜索跑到多个标的上、**共享参数**。一个必须同时在四个标的上成立的规则，无法拟合单个标的的一段行情。这条不需要任何新理论。
2. **修折的设计。** 把折得分改成"相对买入持有的风险调整超额"，这样一个空仓的下跌折会因为"没亏"而得正分；或者按 regime 分层，要求目标函数在每一层都为正。
3. **先诊断"为什么某些折没有交易"**，再往条件目录里加任何新条件。交易笔数一变，下游一切都变。我们那次最大的单项发现其实是一个"漏掉的机会"：某个半年窗口买入持有涨了很多、且大部分时间处于上涨状态，而系统一笔都没开——找出是什么闸门挡住了入场，比再加一个条件值钱得多。

## 三、报告分布，不要报告 argmax

这是写进设计文档的硬约定：

> **必须报告得分分布，而不是 argmax。** 中位折得分、完整的折间分布、得分 vs 复杂度的曲线都要报。argmax 正是 Goodhart 要吃掉的那个东西。

配套的聚合写法（供参考，不是唯一解）：

```
每折得分先年化       # 训练折 1–4 年、测试折半年，不年化则无法比较
S = mean(测试折得分)
    − λ_disp · std(测试折得分)              # 折间离散度惩罚
    − λ_gap  · max(0, mean(训练折) − mean(测试折))   # 训练-测试差距惩罚
S *= N / (N + k)   若 S > 0                 # N = 样本外总往返数；只收缩正分，不收缩负分
```

最后那条"只收缩赢、不收缩输"很重要：小样本的**盈利**要打折，小样本的**亏损**不应该被打折成"看起来没那么糟"。

**年化这一步比看起来重要**：训练折和测试折长度不同时，直接比较原始收益会让每个候选都显得在过拟合，train-test gap 惩罚也就失去意义。

---

## 四、硬拒绝条件，在跑之前写死

分数为 −∞ 的条件（提前提交，不可事后调整）：

- **样本外完整往返数少于某个下限** —— 空仓是合法的策略结果，但一个**被允许选择空仓的搜索**是在躲避自己的目标函数；
- **选择期最大回撤超过上限** —— 否则在较短的测试折里回撤惩罚项永远咬不到，搜索会用回撤换收益然后管它叫 alpha。

这两条的共性是：它们堵的不是"参数不好"，而是**搜索可以走的捷径**。设计目标函数时应该主动去想"如果我是优化器，我会怎么作弊"，然后把那条路堵死。

---

## 五、把约束做成类型，而不是做成配置

这是整套方法里我最推荐复用的一条。

**不变量**：一个被搜索的规则包**只能做减法**。schema 里不存在任何语法能够新增开仓、把仓位放大到规则给出的上限之上、把止损挪远、或者屏蔽止损。

> 这是**类型的性质**，不是配置的性质。

实现层面：入场许可与引擎自身的入场判定做 AND；仓位系数用 `min()` 夹住；软退出的抑制开关只影响软退出，硬止损和追踪止损不受影响。每一条由测试锁定，其中一个测试**对条件目录里的每一条条件做参数化**，这样新加一条条件的那一刻它就自动被覆盖。

同一思路的另一个例子：**每一次止损更新都写成 `max()`（多头）/ `min()`（空头）**。于是"把止损挪远"这件事在代码里**不可表达**——不是被禁止，是无法写出来。

### 5.1 心理学写成结构，而不是写成建议

同一个项目把一组交易心理失败模式逐条映射成结构性约束，并且每条配一个测试：

| 偏差 | 结构性回答 |
|---|---|
| 难受时把止损挪远 | 止损几何在进场时由波动率锁定；每次更新是 `max()`，代码无法表达"挪远" |
| "计划中的亏损感觉太大" | 这是**仓位**信号，不是止损信号。单笔风险上限缩小仓位，直到被止损的代价 ≤ 该比例 |
| 持有已经破论点的亏损单 | 时间止损（仅在亏损时生效）——不工作的资金按进场前定好的时间表召回 |
| 止损后报复性重入 | 冷却期，进场前就承诺好的暂停 |
| 让盈利单变成亏损单 | 达到一定有利幅度后把止损棘轮到成本 |
| 回撤后加码 | 回撤熔断，低于阈值不再开新仓 |

> 写在文档里的纪律会在压力下失效；写成类型和测试的纪律不会。

## 六、什么**不**进搜索空间

每一项都要写出理由，这份"故意不搜"的清单和搜索空间本身一样重要：

| 冻结项 | 理由 |
|---|---|
| 方向许可（是否允许做空） | 先验研究已否定；schema 直接**丢掉这个键**，而不是信任配置里写了 false。有测试断言它无法被设置 |
| 仓位基数 / 加仓比例 / 仓位上限 | 这是**杠杆旋钮**，不是条件。让搜索碰它，"哪些条件好"就变成了"在回撤惩罚咬人之前我能下多大注"。要搜必须显式开一个开关 |
| 核心结构定义（趋势包络等） | 承重件。条件只能从包络里减，不能替换包络 |
| 手续费 | 与纸面账户口径一致，**绝不静默置零** |

## 七、单因子消融：看最优是平台还是尖峰

搜索给出冠军之后，围绕参考参数对每个旋钮做一次单因子扫描。我们那次的结果很有说服力：**赢得搜索的那个旋钮，单独扫描时在两个窗口上都是单调有害的。**

也就是说，冠军是一个**联合参数伪像**，不是一个发现。如果只报冠军而不做消融，这个伪像会被当成"我们发现 X 很重要"写进结论。

同一套逻辑：全量网格的最优值必须落在一片平台上；孤立尖峰等价于"这个结果是被噪声选中的"。

---

## 八、基线不对称：参考臂本身可能是被全样本选出来的

一个容易漏掉的偏差来源：如果你的参考臂（"先前研究的赢家参数"）当初是在**全样本知识**下选出来的，而新搜索的候选是诚实地只用选择期选出来的，那么这个比较**结构性地偏向参考臂**。

处理方式不是放弃比较，而是把方向写清楚：参考臂的数字是乐观的，搜索的数字是诚实的，**所以"搜索输给参考臂"这件事其实低估了搜索输得有多惨**。把偏差的方向写出来，比假装没有偏差有用。

---

## 九、holdout 花掉了就是花掉了

我们用 holdout 做了那次"目标函数是否反预测"的诊断。这个诊断本身是方法论层面的，不是选参数——但结论仍然是：

> **这个 holdout 已经被花掉了。** 它已经产生了一个方法论结论；任何在知道这个结论之后被选出来的候选，都不再被它检验。下一次诚实的检验只能是向前的时间，或者一个还没被看过的标的。

这条很难遵守，因为 holdout 看起来"只用了一次、而且不是用来选参数的"。但信息一旦流出，就流出了。

---

## 十、搜索效率往往不是瓶颈

最后一条，来自另一个项目的自述，值得原样记住：

> 当前的瓶颈是**样本量与经济显著性**，不是搜索效率——在证据变强之前，更聪明的搜索只会更快地过拟合。

同一意思的另一种说法：**在决定"加大搜索"之前，先回答"我的目标函数有没有资格做选择"（第一节的秩相关诊断）和"我的折里有多少笔独立交易"（第二节）。** 这两个问题的答案通常意味着你该去找更多数据，而不是更好的优化器。
