# 模拟盘系统怎么设计才值得信任

模拟盘（paper trading）最容易变成一个自我安慰的玩具：它跑起来了，有曲线，有成交，看上去像那么回事——但它和回测对不上，和实盘也对不上，于是它既不能验证策略，也不能验证工程。

下面这套结构来自一个从零写起的 BTC 永续模拟交易系统，以及一个更轻量的本地回测/纸面交易实验台。核心目标只有一个：**让"回测里发生的事"、"模拟盘里发生的事"、"实盘会发生的事"是同一件事的三次观测，而不是三套独立实现。**

---

## 一、第一原则：结构上杜绝未来函数，而不是靠自律

绝大多数前视偏差不是"写错了一行"，而是**架构允许你写错**。只要策略代码手里握着一整个 DataFrame，它随时可以不小心读到未来。

所以引擎层的硬约束是：

> **事件流是策略的唯一输入。策略类只有 `on_bar(tf, bar)` / `on_feature(...)` 这类回调，没有任何"主动拉取数据"的能力。**

配套的三条：

1. **所有周期一律用"收盘时间戳"索引**，不用开盘时间。一根 4h K 线在它的右边界之前不存在。
2. **多周期对齐器（BarAligner）维护每个周期"最近一根已收盘 K 线"**，低周期只能看到已收盘的高周期。当 15m 的收盘时刻与某根 4h 的收盘时刻**完全重合**时，允许引用那根 4h——这不是泄露，因为那根 4h 的数据本身就截止于同一时刻。
3. **需要右侧确认的东西（分形摆动点、"3 根内收盘跌回"）明确区分"确认延迟"和"未来函数"**：脚本显式记录每个摆动点的 `confirmed_ts = close_ms[i + right]`，下游只允许引用 `confirmed_ts <= 当前决策时刻` 的点；入场时刻和入场价一律定义为**确认那根 bar 自己的收盘**。

这三条写进引擎之后，"策略不小心看到未来"就从一个需要 review 的风险，变成了一个写不出来的代码。

---

## 二、回测 / 模拟盘 / 实盘同源

同源不是口号，它有几个可以落地的检查点。

### 2.1 配置同构

模拟盘配置与回测配置**必须同结构**：`strategy` / `risk` / `exits` 这几段要能直接复制粘贴，模拟盘只额外多出 `ws`、心跳、通知这类运行时字段。只要这几段需要"翻译"，两边就已经开始漂移了。

### 2.2 撮合器同接口

`SimBroker`（回测）与 `PaperBroker`（模拟盘）实现同一个接口。差别只在价格来源：回测用历史 bar / 逐笔，模拟盘用实时盘口。订单语义、手续费口径、资金费结算口径、止损触发口径全部共享。

### 2.3 验收用一致性测试，不用"看起来对"

最有价值的一条验收标准：

> 用 fake WS **回放两天录制的 K 线 + 盘口**，模拟盘产生的交易，与同区间回测（1m 撮合分辨率）的交易，**方向与入场时间必须逐笔一致**（价格允许有差异）。

这条测试抓到的是"两套实现偷偷分叉"这类最难发现的 bug。价格允许差异是因为撮合分辨率不同；方向和时间不允许差异，因为那是策略逻辑本身。

## 三、数据源要和采集器解耦

一个反直觉但重要的决定：**模拟盘不读采集器落的 Parquet，而是自己开一条独立的 WebSocket。**

理由：

- **故障隔离**——采集器挂了，模拟盘照跑；研究用的数据管道和交易用的数据管道不共命运。
- **边界正确性**——直接用交易所推送的已收盘 K 线（只取 `x=true`），不自己重采样，避免自己算的桶边界与交易所差一根。

代价是要自己处理两件事：

1. **同边界到达顺序不保证**：15m / 1h / 4h 的收盘推送可能乱序到达。解决办法是 feed 内部按收盘时间缓冲一小段时间（例如 2 秒），然后按"高周期先"排序发出——否则策略会在高周期状态还没更新时就用低周期做决策。
2. **预热（warmup）**：启动时先用 REST 拉各周期最近数百根离线喂给策略，此期间 `submit` 被忽略但要记录；喂完再切换到实时。**预热期不下单必须有单元测试**，否则每次重启都会在启动瞬间开一笔幽灵仓。

## 四、模拟撮合的口径

模拟撮合的价值全在"口径写死并写下来"，而不是在于它多精细。

| 订单类型 | 口径 |
|---|---|
| 市价单 | 买用 ask、卖用 bid 成交，taker 费；**盘口数据超过 N 秒没更新则直接拒单**，不许用陈旧价格成交 |
| 止损市价 | 两种模式二选一并显式配置：逐笔检查（`intrabar`）或只在收盘检查（`close_confirm`）；触发后以对手价成交 |
| 限价止盈 | 盘口触及即成交，maker 费（这是简化，要在文档里标明） |
| 资金费 | 按 8h 结算边界计费，用标记价流的费率 |

两条容易被忽略的执行细节：

- **止损触发价用标记价，不用最新成交价**。实盘下单时对应 `workingType=MARK_PRICE`。模拟盘如果用 last price 触发，回测出来的止损次数会系统性偏高。
- **同一根 K 线内止损止盈都被触及时，从 K 线数据无法判断先后，一律按"先止损"处理。** 宁可低估也不能高估。

## 五、状态与恢复：7×24 的真实成本

模拟盘要长跑，就必须能重启。

- 状态落 SQLite（`orders / fills / positions / equity / signals / events`），**每次变更立即 commit**。
- 重启流程：读回持仓与挂单 → 预热策略 → 继续。
- **最关键的一条边界**：如果持仓存在但策略内部状态丢了，保留持仓和止损单（由 broker 托管），策略在 `on_start` 里从 `ctx.position` 得知"我已经有仓了"。绝不能因为策略不记得，就静默地把仓位丢掉或者重新开一笔。
- 心跳文件 + 超时告警，复用与采集器相同的 healthcheck 逻辑。
- 验收：写入 → 重启 → 状态一致，必须是一条自动化测试，不是手动点一遍。

## 六、影子曲线：让"要不要改参数"变成观测而不是辩论

模拟盘只跑一条基线曲线是浪费。真正有用的做法是**并行记录一组影子曲线**：同一份信号流，分别按不同的止损宽度 × 不同的 regime 参数 × 不同的仓位算法结算，得到 N 条平行权益曲线。

好处是：

- 想改参数时，你手里已经有这个参数在**同一段真实行情**上的表现，不需要重新跑一遍回测，也不需要等三个月。
- 它天然是一个参数平台检验：如果基线旁边的几条影子曲线都差不多，说明参数落在平台上；如果基线一枝独秀，那多半是被挑出来的。
- 影子曲线的持仓状态**必须跨重启保留**，否则每次重启都把它们清零，攒不出足够长的样本。

同理，那些"还不敢下场交易"的判断（例如某种震荡态标签）可以先以**只观测、不动作**的形式进模拟盘：打标签、进库、进影子曲线，等攒够独立样本再决定要不要接进决策链。

---

## 七、执行禁区：模拟盘里最容易被跳过的一层

模拟盘很容易只模拟"策略说买我就买"，而忽略实盘真正会卡住的那些时刻。把禁区规则写进模拟盘，而不是等到实盘：

- 资金费结算前若干分钟不开新仓；
- 宏观日历事件前后各若干分钟不开新仓；
- 强平爆发之后若干分钟不开新仓；
- 薄流动性时段（深夜 UTC 时段、周末）止损缓冲放宽、强制收盘确认；
- 单笔名义规模不超过盘口 ±0.1% 深度的某个比例。

**每一次被禁区拦下都要发一个 `entry_blocked` 事件并带上规则名**，报告里统计它。否则你永远不知道这些规则到底拦掉了多少交易、代价是什么——而"禁区窗口的具体分钟数"本身通常是纯先验、从未被回测验证过的参数，至少要让它可观测。

---

## 八、盲态回放：把人的决策也变成可分析的数据

如果目的是积累交易经验（而不只是验证一条规则），可以再加一层**盲态 K 线回放器**：用真实历史数据，隐藏真实日期，让人手动交易，记录每一步。

设计要点：

- **分层选段**：用高周期数据自动给历史打上 regime 标签（强趋势 / 弱趋势 / 小震荡 / 大震荡 / 趋势反转 / 熊市反弹 / 牛市回调），每类至少取两段，段与段不重叠，顺序打乱。段的类型与真实日期**只进数据库，不进界面**。
- **排除已知区间**：候选区间必须截止在"用户已经亲历过的行情"之前，否则记忆本身就是前视。
- **显示归一化**：段起点收盘价归一到 100，界面显示"段内第 N 天 HH:MM"。数据库里仍存真实价格与时间。
- **严格 as-of**：任何输出不得包含时钟之后的数据。允许"回退查看"（时钟不动），但"回退重放"必须把此后的交易标记为 `tainted`。
- **记录的是决策上下文，不只是成交**：每个动作附带原因标签（多选：突破 / 回踩 / 供给区 / 结构破坏 / 资金流 / 强平后 / 其他）、信心 1–5，还要有"看到但没进"和"看到但错过"两个按钮——**负样本和正样本一样重要**。

这样产出的数据可以做三件回测做不了的事：人工入场 vs 随机入场（同出场）的对照、人工出场 vs 一直持有的对照、以及用可解释模型（决策树 / 逻辑回归）去看"进场 vs 观望"到底由哪些状态变量区分。提炼要用前半段，验证要用后半段。

---

## 九、一条纪律

> 模拟盘能跑不等于模拟盘可信。可信的唯一证据是：**它和回测在同一段行情上逐笔对得上，它重启之后状态没丢，它的每一条口径都写在文档里。** 三条缺一条，它产出的曲线就只是一张图。
